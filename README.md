# 🐾 멍고반점

> **사진 한 장으로 잃어버린 가족을 찾습니다.**
> 잃어버린 반려동물 사진을 전국 보호소 입소 동물(공공 데이터, 매일 갱신)과
> AI 임베딩 유사도로 대조해, 수백만 건 중에서 닮은 후보를 최대 20건 찾아주는
> 유기동물 라이프사이클(실종 → 구조 → 보호 → 입양/반환) 플랫폼입니다.

**빅데이터 분산 처리 프로젝트 · 팀 meong-go-spot**

## 왜 만드는가

국가는 분실신고와 보호소 입소 데이터를 **양쪽 다** 모으고 있지만, 둘의 연결은 사람이 게시판을 뒤지는 우연에 맡겨져 있습니다 (국가 시스템의 분실신고 게시판은 전국 누적 111건 — 사실상 미사용). **멍고반점은 그 공백을 국내 공공데이터로 채웁니다.**

기존 서비스와의 차별점:

- **사전 등록·앱 생태계 없이** — 이미 잃어버린 뒤에 와도 과거 입소분까지 소급 검색
- **태그 정확 일치가 아닌 임베딩 유사도 랭킹** — "갈색 푸들"과 "적갈색 믹스"처럼 표기가 달라도 만나게 함
- **시공간 추론** — 분실 후 경과일수에 비례한 이동 반경으로 후보 필터링

## 제품 비전 — 단계별 확장

| 기능 | 설명 | 범위 |
|---|---|---|
| 🔍 **실종 동물 찾기** | 본인 활성 실종 게시물에서 분석을 선택하면 사용자·공공 보호동물 후보 최대 20건 제시 | MVP |
| 🔔 **일일 입소 요약** | 일일 증분 적재 성공 후 신규 보호동물 수·보호소 수를 FCM 푸시와 앱 내에서 안내 | MVP |
| 🔔 **개별 신규 후보 알림** | 신규 입소에 따른 자동 재분석과 개별 유사 후보 푸시 알림 | MVP 이후(P1) |
| 🏠 **입양 매칭** | 원하는 외형·조건과 닮은 보호 동물 추천 (보호기간 만료 임박 우선 노출) | MVP 이후(P1) |
| 🐕 **개체 재식별** | 보호소 전체 셀프조인으로 반복 유기·재입소 개체 탐지 | MVP 이후(P1) |
| 📊 **유기 발생 대시보드** | 발생 핫스팟·추이 분석 (지자체용 확장) | MVP 이후(P1) |

## 아키텍처 — 람다(Lambda)

**AI(임베딩)는 이미지를 벡터로 바꾸는 입력 생성 도구이고, 빅데이터 분산 처리가 수백만 벡터를 실제로 연결하는 본체입니다.** 매칭은 쌍(pair) 단위 연산이라 계산량이 n² — 누적 구조동물 수백만 건 × DINOv2 ViT-B/14 768차원이므로 단일 DB 쿼리에 맡기지 않고 사전 계산·블로킹·분산 처리를 사용합니다. 활성 전처리 포함 모델은 `ai/model.yaml`의 v2입니다.

```mermaid
flowchart LR
    A[공공 API<br/>구조·분실동물] --> K[Kafka]
    K --> H[HDFS<br/>원본+이미지]
    H --> M["MapReduce 배치 5종<br/>(kNN·행렬곱·쎄타조인·자카드·K-Means)"]
    M --> R[(유사도·클러스터<br/>결과 적재)]
    K -- 신규 입소 이벤트 --> S[실시간 증분 매칭(P1)<br/>배치 클러스터에 배정]
    R --> S
    S --> P[푸시 알림(P1)]
    K -- 일일 증분 적재 성공 --> D[일일 입소 요약(MVP)<br/>신규 동물 수·보호소 수]
    D --> N[FCM 푸시 + 앱 내 요약(MVP)]
    API -- "M2: PENDING 기록" --> Q[(PostgreSQL<br/>match_run)]
    Q --> W[DATA/AI worker]
    W --> R
    R --> API[Spring Boot API] --> APP[Android 앱]
```

위 구조는 MVP 이후(P1)까지 포함한 목표 아키텍처입니다. MVP에서는 `잃어버렸어요` 등록만으로 분석하지 않고, 본인 활성 게시물 상세에서 사용자가 분석을 선택할 때 `match_run(PENDING)`을 202로 접수해 worker가 단방향 후보를 계산합니다. M2마다 새 YARN 잡을 기동하지 않고 준비된 검색 자산을 사용합니다. 보호센터 데이터는 최초 전체 적재 후 매일 증분 적재하며, 적재 성공 시 신규 보호동물 수·보호소 수만 FCM 푸시와 앱 내 요약으로 안내합니다. 개별 유사 후보의 자동 재분석·푸시 알림은 P1에서 확장합니다.

| 알고리즘 | 담당 기능 |
|---|---|
| kNN 조인 | 분실신고 ↔ 보호동물 Top-K 매칭(MVP K=20) + 입양 추천(P1) — **서비스의 심장** |
| 행렬곱 (스트리밍) | 임베딩 행렬 × 전치 = 동물 간 유사도 행렬 (수백만×768) |
| 쎄타조인 | "분실일 < 입소일 AND 거리 < 경과일수×이동반경" 시공간 부등호 조인 |
| 자카드 셀프조인 | 특징 태그 유사 쌍 + 개체 재식별 |
| K-Means | 외형 클러스터로 후보 공간 축소(블로킹) + 유기 핫스팟 분석 |

## 기술 스택

<sub>MVP 스택은 확정됐으며 모델별 점수 임계값과 평가 조건만 별도 검증합니다.</sub>

| 영역 | 스택 |
|---|---|
| **클라이언트** | Android — Kotlin 2.0 · Jetpack Compose |
| **백엔드** | Java 21 · Spring Boot 4.1 · PostgreSQL 17 · JPA |
| **빅데이터** | Kafka · HDFS · MapReduce (람다 아키텍처) |
| **AI** | YOLO26 탐지·크롭 + DINOv2(frozen) 임베딩 · 속성 자동 추출 · 하이브리드 스코어링 |
| **인프라** | GitLab CI (MR 게이트) · Jenkins (배포) · Docker Compose · Gemini AI 코드 리뷰 |
| **협업** | GitLab (MR) · Jira (이슈·스프린트) · lefthook + commitlint |
