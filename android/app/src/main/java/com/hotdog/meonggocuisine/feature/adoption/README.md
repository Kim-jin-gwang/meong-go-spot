# Adoption (소개팅)

공고가 끝나 입양을 기다리는 보호 동물을 카드로 한 마리씩 넘겨 보는 화면입니다.

## 왜 이 화면이 있나

동물보호법은 보호조치 사실을 **7일 이상 공고**(제40조)하게 하고, **공고한 날부터 10일**이
지나도 소유자를 알 수 없으면 지자체가 소유권을 취득하도록 정한다(제34조제1항제1호). 소유권이
넘어가야 비로소 입양이 가능해진다.

문제는 그다음이다. 공고가 끝난 뒤로는 법이 정한 시한이 더 없고, 보호소 여력에 따라 안락사가
결정된다. 최근 3년 종결 건에서 **안락사가 22.2%**다(`data/collector/shelter_outcomes.py`).
오래 기다린 동물일수록 위험하다.

## 구성

- `ui/AdoptionScreen.kt`: 카드 스택, 좌우 스와이프, 축종 필터, 목적 안내와 관심 표시
- `ui/AdoptionViewModel.kt`: 지역·축종 기준 조회, 카드 인덱스와 관심 표시의 낙관적 갱신
- `ui/AdoptionUiState.kt`: 현재·다음 카드와 소진·빈 결과 상태
- `data/AdoptionModels.kt`: 화면이 쓰는 동물 모델과 축종 필터
- `data/AdoptionRepository.kt` · `data/DefaultAdoptionRepository.kt`: AD1·AD3·AD4 조회·저장 계약과 구현

## 설계 판단

**대상은 공고가 끝난 개체다.** 임의의 기간이 아니라 법이 그은 선이고, 공공데이터포털 구조동물
API가 `state=protect`로 이미 구분해 준다. 공고 중인 동물은 아직 원 소유자의 것이라 입양 신청을
받을 수 없으므로 넣지 않는다.

**정렬은 오래 기다린 순이다.** 공고 종료 뒤로는 카운트다운할 시한이 없어 "만료 임박"이라는
개념이 성립하지 않는다. 지나간 날수가 위험 신호다.

**카드는 남은 날이 아니라 지낸 날을 보여 준다.** 2026-09-17 실측(표본 4,408건) 기준 공고 종료 후
경과일 중앙값이 122일이고 31.9%가 181일을 넘는다. 180일 이상은 배지 색을 바꿔 구분한다.

**지역을 고르지 않으면 목록을 부르지 않는다.** 입양은 보호소에 직접 방문해야 해서 지역이 맞지
않으면 의미가 없다. 관심 지역은 `feature/community`의 `RegionStore`를 함께 쓴다. 전국(`00`)·시·도
전체(2자리)도 서버 AD1이 P1과 같은 규칙으로 받으므로(2026-09-22) 그대로 조회한다 — 전국은 파라미터를
생략한다(`asApiRegionCode`). 화면 상단의 지역 줄(`CurrentRegion`)에서 바로 바꿀 수 있다.

**축종 필터를 둔다.** 실측에서 개가 82.7%라 필터가 없으면 고양이를 찾는 사용자가 한참 넘겨야
한다.

**스와이프 방향은 선택의 의미를 갖는다.** 왼쪽은 좋아요 없이 다음 카드로 넘어가고, 오른쪽은
좋아요를 저장한 뒤 다음 카드로 넘어간다. 기준 거리보다 짧게 움직이면 제자리로 돌아온다.

**좋아요도 그냥 넘어간다.** 한동안 좋아요에는 완료 모션을 줬다 — 카드가 헤더의 마이페이지 버튼
좌표로 작아지며 빨려 들어가고 버튼이 짧게 커졌다 돌아왔다. 어디에 담겼는지 알려 주려던 것인데
넘길 때마다 반 초가 들어 연달아 보기가 답답했다. 지금은 왼쪽이든 오른쪽이든 같은 속도로 화면
밖으로 나가고, 담긴 자리는 히스토리에서 확인한다(2026-09-24). 헤더에는 홈과 같은 위치와 순서로
채팅·마이페이지 버튼을 두며, 비로그인 탭은 로그인 뒤 선택한 화면으로 이어진다.

**넘긴 아이는 다시 올라오지 않는다.** 넘김은 판단이 끝났다는 뜻이라 두 번 물으면 안 된다.
`AdoptionViewModel`이 넘긴 `postId`를 들고 있다가 목록을 다시 받을 때 걸러 낸다 — 화면을 다시
열거나 조건을 바꿔도 마찬가지다. 한 쪽이 통째로 걸러지면 카드가 찰 때까지 다음 쪽을 이어 받는다.
앱을 껐다 켜면 잊는다.

**히스토리는 전체와 좋아요로 나눈다.** 좋아요로 넘겼든 그냥 넘겼든 모두 전체 탭에 쌓이고,
좋아요 탭은 오른쪽으로 넘긴 것만 보여 준다. "아까 그 아이" 를 찾는 것과 "내가 고른 아이" 를
다시 보는 것은 다른 일이라 한 격자에 섞어 두면 둘 다 불편하다.

**히스토리의 하트는 넘긴 방향이지 찜 상태가 아니다.** 서버가 주는 `favorited` 를 그대로 쓰면
예전에 찜해 둔 아이를 이번에 왼쪽으로 넘겨도 하트가 달려서, 왼쪽으로 넘겼는데 좋아요가 되는
것처럼 보였다. `AdoptionSwipeRecord.liked` 에 방향을 따로 적는다(2026-09-24).

**관심 버튼은 카드 밖에 둔다.** 카드 안에 두면 카드를 끄는 동작과 탭이 부딪히고 카드가 길어진다.
밖에 두면 넘겨도 버튼이 제자리에 있어 엄지가 그대로 닿는다.

**아이콘과 글자를 함께 쓴다.** 하트만 두면 "좋아요"인지 "저장"인지 흔들린다. 나중에 공고 중인
동물까지 다루게 되면 같은 버튼이 "알림 받기"가 되는데, 그때 문구만 바꾸면 된다.

**1.6 앱은 소개팅 진입부터 로그인이 필요하다.** 로그인 뒤 `PendingDestination.ADOPTION`으로 이
화면에 이어진다. 서버의 AD1 공개 조회는 1.5 앱을 깨뜨리지 않고 backend를 먼저 배포하기 위한
호환 계약이며, 새 앱의 비로그인 화면 진입을 뜻하지 않는다(2026-09-28).

## 찜한 동물은 어디서 보나

히스토리 탭의 찜 칸에서 본다. 넘김 기록(AD6)이 `favorited`를 함께 내려주므로 따로 부르지 않는다.

마이페이지에 있던 좋아요 목록 화면은 걷어냈다(2026-09-25). 그 화면은 AD2를 부른 적이 없고
`AdoptionFavoriteStore`라는 프로세스 내 임시 저장소만 읽어서, 앱을 다시 켜면 늘 비어 있었다.
서버에 남는 찜을 히스토리가 보여 주게 된 뒤로는 비어 있는 화면 하나가 더 있을 뿐이었다.

**AD2는 서버에 그대로 있고 앱이 쓰지 않는다.** 넘긴 적 없이 찜만 한 동물은 히스토리에 뜨지
않으므로, 그것까지 모아 보여 줄 자리를 만들 때 AD2를 연결한다.
