## 잃어버렸어요 목록

- `ui/LostPostListScreen.kt`: 검색, 필터 시트 열기, 게시물 카드와 로딩·빈 결과·실패 상태
- `ui/LostPostListViewModel.kt`: 선택 지역 구독(보호 목록과 같은 `RegionStore`, 없으면 전국), 품종 검색, 재시도와 커서 기반 추가 조회 상태
- `data/CommunityApi.kt`: 비로그인 게시물 목록 P1 API
- `data/LostPostRepository.kt`: API 응답을 목록 화면 결과로 변환하는 경계

목록 요청은 항상 `type=LOST`를 사용하며 서버가 반환하는 ACTIVE 사용자 게시물만 표시한다. 카드에는 사진, 이름 또는 품종, 동물 정보, 사건 날짜, `EVENT.publicLocation`과 출처 배지만 표시한다. 작성자 정보, 연락처, 정확한 위치와 좌표는 요청하거나 표시하지 않는다.

선택 지역은 P1의 `regionCode`, 품종 검색은 `breedName` 부분 검색을 사용한다. 조회 조건(축종·성별·정렬)은 `data/PostListFilter.kt` 하나로 묶어 `onFilterApply`로 한 번에 넘긴다. 조건이 바뀌면 검색어·선택 지역은 유지하고 목록과 커서를 초기화해 첫 페이지부터 다시 조회한다. 현재 화면 예시는 서울특별시 마포구(`11440`)를 선택한 상태이며, 지역 변경 버튼은 `RegionSelectionRoute`로 연결한다. 카드 선택 시 인증 상태를 확인하며, 비로그인 사용자는 로그인 성공 후 선택했던 `PostDetailRoute`로 이동한다.

## 보호하고 있어요 목록

- `ui/RegionSelectionScreen.kt`: 보호 목록 조회 전에 관심 지역을 시·군·구 단위로 선택하는 화면
- `ui/RegionSelectionViewModel.kt`: 선택 가능한 시·군·구 목록, 기존 선택값 복원, 선택 지역 저장
- `data/SelectedRegionStore.kt`: 앱 재실행 후에도 유지되는 관심 지역 저장소
- `ui/ShelteringPostListScreen.kt`: 보호 게시물 검색, 필터 시트 열기, 출처 배지, 로딩·빈 결과·실패 상태
- `ui/ShelteringPostListViewModel.kt`: 선택 지역 구독, 품종 검색, 재시도와 커서 기반 추가 조회 상태
- `data/ShelteringPostRepository.kt`: 보호 목록 API 응답을 목록 화면 결과로 변환하는 경계

보호 목록 요청은 항상 `type=SHELTERING`과 선택된 `regionCode`, 현재 조회 조건을 함께 사용한다. 단 `sort`가 `LATEST`(서버 기본값)이면 파라미터를 생략한다 — `sort`를 모르는 옛 서버가 400을 주기 때문이다(2026-09-22, v1.3.0 운영에서 목록이 비었던 원인). 관심 지역이 아직 없으면 `ShelteringPostListViewModel`은 API를 호출하지 않고 `RegionSelectionRoute`로 이동할 수 있는 상태만 제공한다.

보호 목록은 사용자 보호 게시물(`USER_POST`)과 공공 보호동물(`SHELTER`)을 같은 목록에 표시한다. 목록 카드에는 사진, 이름 또는 품종, 동물 정보, 사건 날짜, 공개 지역과 출처 배지만 표시한다. 보호소 이름, 보호소 전화번호, 정확한 주소, 작성자 개인정보는 목록 화면에 표시하지 않는다.

두 목록의 카드·검색줄은 `ui/CommunityPostComponents.kt` 하나를 함께 쓴다. 같은 `LostPostSummary`를 같은 모양으로 보여 주는데 화면마다 사본을 두면 한쪽만 손볼 때 디자인이 갈라지기 때문이다. 카드에 담는 값은 사진, 이름 또는 품종, 성별, 사건 날짜, 공개 지역, 출처다. 응답의 `color`와 `listedAt`은 카드에 쓰지 않는다 — `listedAt`은 정렬 기준이고, `color`는 목록에서 뺐다. 축종도 카드에 적지 않는다 — 사진과 품종에 이미 드러나고, 축종으로 좁히는 건 필터 시트가 맡는다.

출처 배지는 제목 오른쪽에 회백 면으로 조용히 둔다. 없애지는 않는다 — `UI-04`와 `UR-DAT-003`(Must)의 인수 조건이고, 보호소 게시물은 전화, 사용자 게시물은 채팅으로 연락 방법이 달라 목록에서부터 구분이 필요하다.

## 조회 조건 (필터 시트)

축종·성별·정렬은 `ui/CommunityFilterSheet.kt` 한 곳에서 고른다. 검색줄 오른쪽의 필터 버튼이 시트를 열고, 조건이 기본값보다 좁혀져 있으면 버튼에 점을 찍는다(`PostListFilter.isNarrowed`). 목록 위에 정렬 줄을 두던 때보다 세로가 한 카드만큼 늘고, 조건이 늘어도 목록 화면은 그대로다.

고른 값은 `적용하기`를 누를 때까지 시트 안에만 둔다. 고를 때마다 조회하면 성별을 바꾸는 사이에 목록이 두 번 갈아엎인다. `전체`는 파라미터를 보내지 않는다 — 서버에 전체를 뜻하는 값이 따로 없어 생략해야 전체가 된다.

**사건 날짜 범위는 넣지 않았다.** 서버가 받는 목록 파라미터에 날짜가 없다(`PostListInputPolicy` 화이트리스트: type·species·sex·breedName·regionCode·color·source·sort). 응답에 `eventDate`가 오지만 그건 받아 온 페이지 안에서만 걸러낼 수 있어 커서 페이지네이션과 맞지 않는다 — 첫 페이지가 전부 기간 밖이면 뒤 페이지에 있어도 빈 화면이 된다. 서버에 날짜 파라미터가 생기면 시트에 섹션 하나를 더하는 것으로 끝난다.

**성별을 고르면 미상이 빠진다.** 보호소 데이터에 성별 미상이 흔한데, `수컷`이나 `암컷`을 고르면 미상인 게시물은 목록에 오지 않는다. 잃어버린 아이를 찾는 사람이 성별을 알고 조건을 걸어도 그 아이가 미상으로 등록돼 있으면 놓칠 수 있다. 서버 `sex`가 값 하나만 받아 "수컷 또는 미상"을 한 번에 요청할 수 없다.
