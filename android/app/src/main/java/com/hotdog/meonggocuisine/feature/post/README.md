# Post

사용자 게시물 상세·수정·종료 화면과 게시물 상세 조회, 변경 데이터 계층을 담당합니다.

## 구현 범위

- `data/PostApi.kt`: 게시물 상세 조회 API를 정의합니다.
- `data/PostDetailModels.kt`: 실종·보호 사용자 게시물과 보호소 게시물을 함께 표현하는 응답 모델입니다.
- `data/DefaultPostDetailRepository.kt`: 네트워크 오류, 미존재 게시물, 일반 실패 메시지를 구분합니다.
- `ui/PostDetailViewModel.kt`: 상세 응답을 화면 표시 모델로 변환하고 권한별 액션 노출 여부를 계산합니다.
- `ui/PostDetailScreen.kt`: 실종 게시물, 사용자 보호 게시물, 보호소 보호동물 상세 UI를 구성합니다.
- `data/PostEditModels.kt`: P4 수정, P5 사진 교체, P6 종료 응답 모델입니다.
- `data/PostEditRepository.kt`: 수정 입력, 종료 사유(`PostCloseReason`)와 결과 계약입니다.
- `data/DefaultPostEditRepository.kt`: 오류 코드를 버전 충돌·공개 동의·권한·상태·사진 오류로 분류합니다.
- `ui/edit/PostEditScreen.kt`: 기존 값으로 채운 수정 폼, 사진 전체 교체, 위치별 공개 스위치를 구성합니다.
- `ui/edit/PostEditViewModel.kt`: 상세로 폼을 초기화하고 P4에 이어 필요할 때 P5를 호출합니다.
- `ui/edit/PostEditInputValidator.kt`: 날짜·시간 형식과 한국 시간 기준 날짜 상한을 선검증합니다.
- `ui/close/PostCloseScreen.kt`: 종료 사유 선택, 종료 후에 남는 것 안내와 확인 다이얼로그를 구성합니다.
- `ui/close/PostCloseViewModel.kt`: 종료 가능 여부를 확인하고 확인 단계를 거쳐 P6을 호출합니다.

## 화면 규칙

- 본인 실종 게시물에는 유사도 분석, 수정, 종료 액션을 표시합니다.
- 다른 사용자의 활성 사용자 게시물에는 채팅 액션만 표시합니다.
- 본인 보호 게시물에는 수정, 종료 액션을 표시합니다.
- 공공 보호동물 게시물은 보호센터 이름·공식 전화번호·주소와 공고 정보를 표시하고, 채팅 대신 전화 걸기 동선을 제공합니다.
- 사용자 연락처는 화면에 표시하지 않습니다.
- 정확한 위치는 해당 위치의 `exactLocationVisible`이 참일 때만 사용하고, 그 밖에는 공개 지역을 표시합니다.
- 유사도 점수, 백분율, 좌표는 상세 화면 모델에 두지 않습니다.

## 공공 보호동물 연락 동선

보호센터 전화번호는 `ACTION_DIAL`로 기본 전화 앱에 채워 넣습니다. 통화 권한이 필요한 직접
발신은 사용하지 않으며, 발신 여부는 사용자가 전화 앱에서 확인합니다.

## 수정 화면 규칙

- 본인의 활성 사용자 게시물만 수정한다. 공공 보호동물, 다른 회원 게시물, 종료 게시물은 화면을
  열지 않고 이유를 알린다. 서버도 매 요청마다 같은 조건을 검증한다.
- 폼은 상세(P2)의 작성자용 응답으로 초기화한다. 비공개로 저장된 정확한 위치도 채워 사용자가
  다시 입력하지 않게 한다. 좌표는 서버가 작성자에게도 주지 않으므로 화면에 두지 않는다.
- 동물 종류(`species`)와 게시물 유형(`type`)은 서버가 변경을 허용하지 않아 읽기만 표시한다.
- 요청이 실패하면 입력과 선택 사진을 `UiState`에 그대로 유지하고 오류만 알린다.
- 값을 비운 선택 필드는 명시적 null로 보내 서버가 삭제하도록 한다. 앱의 Json 설정이
  `explicitNulls = false`라 데이터 클래스로는 생략과 삭제를 구분할 수 없어 P4 payload만
  `JsonObject`로 만든다.
- 사진은 P5 계약대로 전체 교체만 한다. 기존 사진은 서버 URL이라 그대로 다시 올릴 수 없어
  부분 삭제·추가를 제공하지 않는다. 새로 고르지 않으면 P5를 호출하지 않는다.
- P4가 성공하면 그 응답의 version으로 P5를 호출한다. 사진 교체만 실패하면 올라간 version을
  보존해 사진만 다시 시도할 수 있게 한다.

## 버전 충돌과 공개 동의

- `POST-004`는 일반 오류와 구분해 안내하고 최신 내용을 다시 불러오는 동선을 제공한다. 다시
  불러오면 입력이 서버 값으로 바뀌므로 그 사실을 함께 알린다.
- 위치별 공개 스위치는 `OFF -> ON`에서만 공개 대상과 범위를 확인하는 다이얼로그를 띄우고,
  확인해야 켜진다. `ON -> OFF`는 추가 확인 없이 즉시 반영한다.
- 공개를 켜거나 공개를 유지한 채 정확한 위치를 바꿀 때만 `exact-location-v1`을 요청에 넣는다.
- `POST-007`은 입력을 보존하고 이번에 켠 스위치만 되돌려 안내를 다시 확인하게 한다.
- 스위치는 색상만으로 상태를 알리지 않고 상태 문구와 접근성 상태 설명을 함께 제공한다.

세부 계약은 `docs/post-date-location-policy.md` 4~6과 `docs/api-spec.md` P4·P5를 따른다.

## 종료 화면 규칙

- 종료는 되돌릴 수 없으므로 사유를 고른 뒤 확인 다이얼로그를 한 번 더 거친다.
- 사유는 서버 `CloseReason`인 `RETURNED`, `TRANSFERRED`, `OTHER` 세 가지만 제공한다.
- 종료 즉시 공개 목록과 새 유사 후보에서 제외되고 MVP에서는 되돌릴 수 없다는 점을 먼저 알린다.
- 종료 후에도 내 게시물 관리의 종료 이력과 읽기 전용 채팅이 남는다는 점을 함께 안내한다.
- 종료 성공 후에는 상세로 돌아가지 않고 내 게시물 관리로 이동한다. 종료된 상세는 수정·종료
  동선을 제공하지 않는다.
