# 게시물 조회 안내

> 구현 상태(2026-09-21): P1 공개 목록은 `LATEST`·`OLDEST`를 지원한다. P7 내 게시물은
> 최신순 고정이며 `sort`를 받지 않는다. 계약은 [API 명세](../../docs/api-spec.md) P1·P7을 따른다.

P1 공개 목록, P2 공개 상세, P7 내 게시물을 제공합니다. 계약 원본은
[API 명세](../../docs/api-spec.md)의 P1·P2·P7과
[날짜·위치 정책](../../docs/post-date-location-policy.md)입니다.

## 목록 호출

- `GET /api/v1/posts?type=LOST`: 비로그인 가능, ACTIVE 사용자 실종 게시물
- `GET /api/v1/posts?type=SHELTERING&regionCode=11680`: 해당 EVENT 시군구의 ACTIVE 사용자·공공 게시물
- `GET /api/v1/members/me/posts`: 로그인 회원의 USER_POST, ACTIVE 및 종료 후 90일 이내 CLOSED

공개 목록의 `species`, `sex`, `breedName`, `color` 필터를 함께 적용할 수 있습니다.
`source=USER_POST|SHELTER`는 SHELTERING에서만 허용하고 LOST에서는 POST-006입니다.
지역 필터는 **EVENT.region_code의 5자리 코드 일치**입니다. 과거 Jira의 지역명 검색 문구는
확정 API 계약으로 대체되었습니다. 읽기는 저장된 코드와 표시값을 사용하므로 현재 등록용
지역 기준 데이터에서 비활성화된 코드의 과거 게시물도 조회할 수 있습니다.

품종·색상은 원문 100 Unicode code point 이하를 검증한 뒤 NFC·양끝 공백 제거를 적용합니다.
대소문자를 구분하지 않는 부분 검색이며 `%`, `_`, 역슬래시도 일반 문자로 비교합니다.
제어 문자·포맷 문자·잘못된 surrogate, 미등록/중복 query parameter는 COMMON-001입니다.
내 게시물은 `type`, `status=ACTIVE|CLOSED`, `cursor`만 받으며 `sort`는 허용하지 않습니다.

공개 목록은 `sort=LATEST|OLDEST`를 받으며 생략하면 `LATEST`입니다. `LATEST`는 저장된
`(listedAt DESC, postId DESC)`, `OLDEST`는 `(listedAt ASC, postId ASC)`을 사용하고 페이지
크기는 항상 10입니다. 허용 목록 enum과 고정 SQL 분기를 사용하므로 요청값을 `ORDER BY`에
직접 넣지 않습니다.
11건을 읽어 `hasNext`를 결정하며 다음 페이지가 있을 때만 `nextCursor`를 제공합니다.
다음 호출에서는 필터와 정렬을 그대로 유지하고 커서를 전달합니다. 커서는 조회 위치와 정규화한
필터·조회 범위·정렬을 담으며, 형식 오류나 다른 필터·정렬·회원의 커서는 CURSOR-001로 거부합니다.
커서는 권한 증명이 아니며 DB 쿼리가 매번 공개 상태와 소유자를 확인합니다.
키셋 커서는 직전 페이지의 마지막 `(listedAt, postId)` 다음 구간만 조회합니다. 페이지 사이에
현재 커서보다 이미 지나간 방향에 항목이 추가되면 이후 페이지에 끼어들지 않고, 아직 조회하지
않은 방향에 추가된 항목은 표시될 수 있습니다. 목록 전체의 스냅샷은 아니므로 종료·삭제된
항목은 다음 호출부터 사라집니다.

공공 `listedAt`의 공고 시작일 → 사건 날짜 → 최초 수집 시각 우선순위는 수집기가 저장할 때
적용하는 ERD 계약입니다. 조회 API가 공고 날짜로 값을 다시 계산하거나 수정하지 않습니다.
목록은 EVENT 공개 위치와 대표 사진만 포함하며 작성자, 보호소 연락처·주소, 정확한 위치,
좌표, 현재 보호 위치와 전체 특징을 반환하지 않습니다.

## 상세와 위치 공개

`GET /api/v1/posts/{postId}`는 비로그인도 조회할 수 있습니다(2026-09-21 QA로 공개 전환).
사용자 상세에는 작성자와 채팅 가능 여부, 소유 여부·버전이 있고, 공공 상세에는 보호소 정보가
있습니다. 출처별 DTO로 필드 혼입을 막습니다.
보호소 전화는 원천 값이 없으면 필드를 유지한 `null`입니다.

사용자 게시물의 각 위치 역할은 별도로 판단합니다. 작성자는 비공개 정확한 위치와 공개 여부를
관리할 수 있고, 다른 로그인 회원은 ACTIVE이면서 현재 정책 동의·동의 시각·공개 설정이 있는 위치만
확인합니다. 비로그인 상세에는 공개 동의 여부와 관계없이 정확한 위치를 싣지 않습니다. 공개하지 않을 암호문은 SQL에서부터 선택하지 않습니다. 좌표와 동의 증빙은
응답하지 않습니다. 상세는 읽기 전용 repeatable-read 트랜잭션으로 게시물·위치·사진을 함께 읽습니다.

USER CLOSED는 90일 보관 기간 안에서 상세와 내 목록에 남습니다. 다른 회원에게는 종료 상세의
정확한 위치를 숨기고 `photos=[]`를 반환합니다. 이는 종료 사진을 작성자만 조회할 수 있는 P8과
동일한 접근 범위입니다. 종료 상세의 채팅 사유는 POST_NOT_ACTIVE입니다. 보관 기간이 지나거나
삭제·탈퇴 상태이면 POST-001입니다. 공공 CLOSED 상세는 과거 매칭 후보 확인을 위해 유지합니다.

사용자 사진은 `/api/v1/photos/{photoId}`, 공공 사진은 자격 증명 없는 유효한 HTTP(S) URL만
반환합니다. 조회 중 HDFS 파일이나 외부 이미지를 읽지 않습니다. 응답은 `Cache-Control: no-store`입니다.

## 검증과 운영

`PostListApiTest`, `PostCursorCodecTest`, `PostDetailApiTest`가 정렬, 필터, 페이지 경계, 커서 오류,
출처·권한·보존 기간, 위치 및 사진 노출을 검증합니다. `SessionApiTest`는 공개 GET과 보호 경로의
인증 경계를 확인합니다. 전체 검증은 저장소 루트의 `npm run check`입니다.

스키마·새 환경변수는 추가하지 않습니다. 기존 [등록 설정](post-creation-guide.md)의 지역 기준
데이터와 위치 암호화 키 준비는 계속 필요하며, 상세의 허용된 위치 복호화에 기존 키링을 사용합니다.
