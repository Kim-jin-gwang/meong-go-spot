## 3. 검증

- 형식: `사진ID<TAB>768값`(소수 6자리), 첫 tar 1,997행 = 성공 수. L2 노름 표본 1.0000. `_meta.json`의 model_id·version·dim·normalized·detector가 `ai/model.yaml`과 일치
- 같은 개체 사진 1·2의 코사인 유사도(2024-01 첫 tar, 15쌍) 평균 **0.748** vs 무작위 쌍 500개 평균 **0.155** — 벡터가 개체 동일성을 담고 있음. 단 쌍별 편차가 커(0.30~1.00) Top-K 정확도는 평가 하네스(-108)에서 측정
- 장치: `nvidia-smi --query-compute-apps`에서 러너 PID가 bus `00000000:61:00.0`(GPU 1)에만 붙음 — 공용 서버 가이드(`CUDA_DEVICE_ORDER=PCI_BUS_ID`, `CUDA_VISIBLE_DEVICES=1`) 준수

## 4. 발견

- **폴백 12.1%**: YOLO가 개·고양이를 찾지 못해 원본 전체로 임베딩한 사진. 탐지된 경우 신뢰도 중앙값 0.93, 하위 10% 0.71. AI팀 부하 테스트 표본(30장 중 20장 탐지, 폴백 33%)보다 실데이터 대량에서는 낫다. 폴백 벡터는 배경이 섞여 매칭 품질이 다를 수 있으므로 평가에서 폴백 여부별 recall을 분리해야 한다(`detections-*.jsonl`로 구분 가능)
- **축종 혼입**: 첫 레코드가 너구리인데 YOLO(대상 클래스 cat·dog)가 신뢰도 0.54로 탐지. 수집기는 축종 필터 없이 전체를 받으므로 매칭 후보는 하류에서 `upKindCd`(축종)로 걸러야 한다
- **보호소 워터마크**: 사진 하단에 협회 로고가 크게 박혀 있고 크롭 박스가 일부 포함한다. 같은 보호소 사진끼리 로고 때문에 가까워질 가능성 → 평가에서 "같은 보호소 다른 개체" 쌍의 유사도를 따로 본다
- **중복 사진 쌍**: 사진 1·2가 같은 파일인 레코드가 있다(코사인 1.000). 정답쌍 세트에서 제외해야 recall이 부풀지 않는다
- 오류 1건: 디코딩 불가 파일 1장(detections에 `error`로 기록)

## 5. 운영 기록

- GPU 서버는 TLJH 환경이라 시스템 python에 torch가 없어 `~/embed-venv`를 만들었다. cu128 인덱스의 torch 최신은 2.11.0
- `model.yaml`의 가중치 절대 경로(`/home/ubuntu/ai/...`)는 서버 2 기준이라 GPU 서버에서 권한 거부 → 러너가 `--ai-dir/models/` 아래에서 해석(MR !75)
- GPU 서버 → 서버 2 SSH는 전용 ed25519 키(`~/.ssh/config` Host 항목)로 열었고 pem은 옮기지 않았다. 코드·가중치·torch hub 캐시는 서버 2 `~/gpu-bundle/`에서 scp
- 실행 시작 시점에 GPU 0·1을 다른 python 프로세스가 쓰고 있었지만 실행 중 종료돼 GPU 1을 단독 사용했다
