# 입양 탐색 P1 MVP 계약

> 상태: **개발 기준 확정**
> Jira: #157
> 기준일: 2026-09-17 (2026-09-28 개정 — 앱 로그인 필수, AD1 서버 선배포 호환, 넘김 기록 저장, 성별 필터)

## 1. 목적과 범위

입양 탐색은 공공 보호동물 가운데 공고가 끝난 뒤에도 보호 중인 동물을 카드로 탐색하고,
관심 동물을 찜한 뒤 기존 로그인 상세에서 보호소 공식 연락처를 확인하는 P1 기능이다.
기존 실종 동물 매칭 MVP와 별도 흐름이며, 이 문서가 입양 탐색의 백엔드·Android 공통 계약이다.

**1.6 앱에서는 로그인한 회원만 쓴다.** 넘긴 동물을 기억해 다시 보여 주지 않으려면 누가 넘겼는지
알아야 한다. 기억이 기기에만 남으면 앱을 지웠다 깔거나 기기를 바꿀 때 처음부터 다시 보게 되므로
회원 계정에 남긴다(2026-09-25). 다만 backend를 앱보다 먼저 배포할 수 있도록 AD1은 1.5 앱의
비로그인 조회 계약을 유지한다. 이 호환 요청에는 회원별 넘김 제외·찜 상태를 적용하지 않는다
(2026-09-28).

이번 범위에 포함하는 기능은 다음과 같다.

- 로그인 회원의 입양 후보 카드 목록
- 선택 지역·축종·성별 필터
- 공고 종료 후 경과일이 긴 동물을 먼저 보여 주는 결정적 커서 페이지네이션
- 넘긴 동물 기록과 다음 조회에서의 제외
- 넘긴 동물 목록(히스토리) 조회
- 회원의 찜 추가·해제·목록
- 찜한 동물의 현재 이용 가능 여부 확인
- 기존 공공 보호동물 로그인 상세를 통한 보호소 공식 연락처 확인

다음 기능은 검증 가능한 원천 데이터와 별도 계약이 마련될 때까지 포함하지 않는다.

- 가정 환경·성격 프로필 저장과 프로필 기반 개인화 점수
- 사진·품종으로 성격, 아동 친화성, 다른 동물과의 적합성을 추정하는 기능
- 근거 원천이 없는 안락사 위험, 입양 가능성, 궁합 백분율 표시
- 넘긴 방향(찜·건너뜀)을 근거로 한 추천 학습, 자동 신청, 결제, 보호소 업무 처리

넘김 기록은 **같은 동물을 두 번 묻지 않기 위해서만** 쓴다. 어느 쪽으로 넘겼는지는 저장하지 않으며
(§6), 취향을 추론하거나 다음 카드 순서를 바꾸는 데 쓰지 않는다. 정렬은 §3 그대로 공고 종료일 순이다.

## 2. 후보 자격과 상태

서버의 `Asia/Seoul` 기준 조회일에 아래 조건을 모두 만족한 건만 입양 후보 목록에 포함한다.

1. `animal_case.source_type=PUBLIC`
2. `animal_case.case_type=SHELTERING`
3. `animal_case.status=ACTIVE`
4. `shelter_animal.process_state_raw='보호중'`
5. `shelter_animal.notice_end_date IS NOT NULL`
6. `shelter_animal.notice_end_date < 조회일`
7. 공개 가능한 대표 사진이 존재한다.

원천 상태는 허용 목록으로 판정한다. 값이 없거나 새 값·종료 상태처럼 해석이 불확실하면 후보에서
제외한다. `notice_end_date` 당일은 아직 공고 종료 후가 아니므로 포함하지 않는다. 공공데이터 지연이나
실패를 후보 없음으로 해석하지 않으며 D1의 마지막 정상 갱신 시각과 상태를 그대로 사용한다.

카드의 `daysSinceNoticeEnd`는 `조회일 - noticeEndDate`의 달력 날짜 차이다. 시간대나 요청 시각에 따라
같은 날 값이 달라지지 않도록 주입 가능한 `Clock`과 `Asia/Seoul`을 사용한다.

## 3. 탐색·정렬·반응

- `regionCode`는 선택이다. 5자리는 `EVENT.region_code`와 정확히 일치, 2자리는 그 시·도 전체,
  없으면 전국이다 (2026-09-22 P1·D3와 같은 규칙으로 완화).
- `species`는 `DOG`, `CAT` 또는 생략(전체)만 허용한다.
- `sex`는 `MALE`, `FEMALE` 또는 생략(전체)만 허용한다. 원천 성별이 `UNKNOWN`인 동물은 성별을
  고르면 제외한다 — 고른 성별이 맞는지 확인할 수 없는 건을 섞으면 필터가 뜻을 잃는다(2026-09-25).
- 후보는 `notice_end_date ASC, animal_case.id ASC`로 정렬한다. 공고 종료일이 오래된 동물이 먼저다.
- 한 페이지는 10건이며 서버는 11건을 읽어 `hasNext`를 계산한다.
- 커서는 공고 종료일, 게시 건 ID, 필터를 결합한 서버 발급 불투명 값이다. 다른 필터에 재사용하면
  `CURSOR-001`을 반환한다.
- **넘긴 동물은 기록하고 다음 조회에서 제외한다.** 오른쪽·왼쪽 어느 쪽으로 넘겼든 한 행을 남기며,
  후보 목록은 그 행이 있는 동물을 빼고 돌려준다. 거르는 일은 서버가 한다 — 클라이언트가 받아서
  걸러 내면 10건을 요청해 몇 건만 남는 페이지가 생긴다(2026-09-25).
- 하트 선택만 찜으로 저장한다. 같은 찜 추가·해제 재요청은 각각 멱등하게 204를 반환한다.
- 찜과 넘김은 서로를 바꾸지 않는다. 하트로 넘기면 두 행이 함께 생기고, 찜을 해제해도 넘김 기록은
  남아 그 동물은 후보로 다시 올라오지 않는다.

입양 후보 목록은 현재 자격을 만족하는 항목만 반환한다. 찜 목록과 넘김 목록은 자격을 잃은 동물도
행을 유지하고 `availability=UNAVAILABLE`로 반환한다. 원천 데이터가 다시 자격을 만족하면
`AVAILABLE`로 계산한다. 찜 목록은 `favoritedAt DESC, postId DESC`로, 넘김 목록은
`swipedAt DESC, postId DESC`로 정렬한다.

## 4. 공개 정보와 연락 흐름

입양 후보·찜·넘김 카드에는 다음 정보만 제공한다.

- 게시 건 ID, 축종, 품종, 성별, 색상
- `EVENT.publicLocation`
- 대표 사진 URL
- 공고 종료일, 공고 종료 후 경과일, 마지막 원천 동기화 시각
- 찜 목록의 찜 시각과 현재 이용 가능 여부
- 넘김 목록의 넘긴 시각, 현재 이용 가능 여부, 현재 찜 여부

카드에는 보호소 이름·전화번호·주소, `CURRENT` 위치, 정확한 위치, 좌표,
`process_state_raw`를 포함하지 않는다. 로그인 후 기존 `GET /api/v1/posts/{postId}` 상세에서만
보호소 이름·공식 전화번호·주소를 확인한다. 연락은 사용자가 보호소에 직접 문의하는 것으로 끝나며,
서비스가 입양 자격이나 신청 완료를 보증하지 않는다.

카드는 `공고 종료 후 N일`로 표현한다. 이 값은 실제 입소일부터 계산한 총 보호 기간이 아니므로
`보호소에서 N일째`로 바꾸어 쓰지 않는다. `안락사 임박`, `입양 확률`, `성격이 잘 맞음` 같은 표현은
검증된 원천 필드와 별도 정책 없이는 사용하지 않는다.

## 5. 화면·오류 상태

| 상태 | 화면·클라이언트 동작 |
|---|---|
| 비로그인 진입 | 로그인·회원가입으로 보내고 인증 뒤 이 화면으로 이어 준다. AD1을 호출하지 않는다. |
| 첫 조회 중 | 카드 자리 로딩 상태를 표시한다. |
| 후보 있음 | 현재 카드와 다음 카드를 표시하고 `hasNext=true`면 다음 커서를 미리 조회할 수 있다. |
| 후보 없음 | `items=[]`과 200을 빈 상태로 표시한다. 공공데이터 지연·실패와 구분한다. |
| 모두 확인 | 현재 묶음과 다음 페이지가 모두 소진됐음을 표시하고 필터 변경·새로고침을 제공한다. 되돌릴 카드가 없으므로 "처음부터 다시 보기"는 두지 않는다. |
| 잘못되거나 날짜가 지난 커서 | `CURSOR-001`을 받으면 저장한 커서를 버리고 첫 페이지부터 다시 조회한다. |
| 넘김 기록 실패 | 카드는 그대로 넘기고 화면을 멈추지 않는다. 다음 목록 조회가 서버 기준으로 맞춰 주므로 그 동물이 한 번 더 올라올 수 있다. |
| 찜 추가 중 자격 상실 | `ADOPTION-001`을 받으면 카드에서 제거하고 목록을 갱신한다. |
| 찜한 동물 자격 상실 | 찜 목록에 `UNAVAILABLE`로 표시하고 보호소 문의를 입양 가능 보장처럼 안내하지 않는다. |
| 넘긴 동물 자격 상실 | 넘김 목록에 `UNAVAILABLE`로 표시하고 칸을 말없이 빼지 않는다. |
| 일시 오류 | 현재 카드를 유지하고 재시도를 제공한다. 넘김이나 하트 성공으로 오인하지 않는다. |

`breedName`과 `color`는 원천에 없으면 `null`일 수 있다. 화면은 각각 `품종 미상`, 색상 생략으로
처리하고 서버가 확인되지 않은 값을 만들어 넣지 않는다.

## 6. 저장·개인정보·삭제

첫 범위에서 지역과 축종은 요청 필터일 뿐 회원 프로필로 저장하지 않는다. 가정 환경·성격·주거 형태,
가족 구성, 다른 반려동물 정보도 수집하지 않는다. 따라서 #158의 가정 프로필 API는 이번
계약에서 구현하지 않고 검증된 동물 특성 데이터가 확보된 뒤 별도 개인정보 고지·보존 기간과 함께
다시 설계한다.

`adoption_favorite`에는 회원 ID, 공공 보호동물 게시 건 ID, 찜 시각만 저장한다. 회원 탈퇴 즉시 인증과
조회 접근을 차단하고, 탈퇴 후 30일 관계형 데이터 파기 작업이 회원의 찜을 명시적으로 제거한다.
회원이나 참조 공공 건을 물리 삭제하는 경우에는 FK `CASCADE`도 정리 안전망으로 동작한다.
공공 동물이 후보 자격을 잃어도 찜은 사용자가 직접 해제하거나 회원 데이터·참조 공공 건이 파기될
때까지 유지한다.

`adoption_swipe`에도 회원 ID, 공공 보호동물 게시 건 ID, 넘긴 시각만 저장한다. **어느 쪽으로
넘겼는지는 저장하지 않는다.** 방향을 남기면 찜과 같은 뜻의 데이터가 두 곳에 생겨, 찜을 해제했을 때
한쪽만 지워져 어긋난다. 찜 여부는 언제나 `adoption_favorite` 하나가 정답이고 `adoption_swipe`는
"이 동물을 이미 봤다"만 뜻한다(2026-09-25). 보관·파기는 찜과 같다 — 회원 탈퇴 30일 뒤 관계형 파기
작업이 함께 제거하고 FK `CASCADE`가 안전망으로 동작한다.

넘김 기록은 지우는 화면을 두지 않는다. 사용자가 되돌릴 수 있게 하려면 "다시 보기" 흐름과 그때의
정렬 규칙을 따로 정해야 하므로 이번 범위 밖이다.

향후 프로필을 도입할 때에도 회원이 직접 입력한 정보만 사용하고 사진·품종 기반 성격 추정을 하지
않는다. 추천 이유는 저장된 검증 사실로 역추적할 수 있어야 하며, 원시 점수나 확률처럼 오해할 값을
사용자에게 제공하지 않는다.

## 7. 상태 변경과 신선도

- 목록과 찜·넘김 조회 때마다 현재 `animal_case`, `shelter_animal` 값을 기준으로 자격을 계산한다.
- 입양·반환·종료 등으로 원천 상태가 바뀌면 다음 정상 수집 뒤 후보 목록에서 제외한다.
- 찜·넘김 목록은 자격 상실 건을 `UNAVAILABLE`로 표시하고 상세·연락을 입양 가능 보장으로 표현하지 않는다.
- 각 카드의 `lastSyncedAt`은 해당 `shelter_animal.last_synced_at`이다.
- 전체 수집 지연·실패 안내는 D1을 사용한다. 마지막 정상 데이터가 있으면 목록 자체를 오류로 바꾸지
  않는다.

## 8. 후속 이슈 구현 순서

1. #160: 이 문서의 후보 자격·정렬·커서로 AD1을 구현한다.
2. #162: `adoption_favorite`와 AD2~AD4를 구현한다.
3. #166: 원천 상태 변경, `UNAVAILABLE`, `lastSyncedAt` 전파를 검증한다.
4. #173: 확정된 API를 Android 카드 스택·찜 화면에 연결한다.

2026-09-25 개정으로 다음이 더해진다. Jira 이슈는 월요일 팀 회의에서 만든다.

5. `adoption_swipe`와 AD5·AD6을 구현하고 AD1에 인증 회원의 넘김 제외·성별 필터를 더한다. AD1의
   비로그인 서버 호환 계약은 유지한다.
6. Android 소개팅 진입에 로그인을 요구하고, 히스토리를 AD6·AD2로 잇는다. 찜 해제는 히스토리와
   상세 팝업에서 한다. 마이페이지의 찜 목록 화면은 히스토리가 대신하므로 없앤다.

#158과 #161은 검증된 동물 특성 입력과 개인정보 정책이 정해질 때까지
구현 선행 조건을 충족하지 않는다.

## 9. 인수 조건

- 공고 종료 전·종료 당일·종료 후 비보호 상태·사진 없는 건이 목록에서 제외된다.
- 공고 종료 후 `보호중`인 사진 보유 건만 지역·축종 필터에 맞게 오래된 공고 종료일 순으로 반환된다.
- 같은 공고 종료일에서도 커서 페이지 간 중복·누락이 없다.
- 1.6 앱은 비로그인 상태에서 AD1을 호출하지 않고 로그인으로 보낸다. 1.5 호환 비로그인 AD1 요청은
  후보 목록을 받되 회원별 넘김 제외 없이 `favorited=false`를 받는다.
- 후보 목록에 보호소 연락처·주소와 정확한 위치가 없다.
- 성별을 고르면 그 성별만 오고 원천 성별이 `UNKNOWN`인 동물은 오지 않는다.
- 넘긴 동물은 같은 회원의 다음 후보 조회에 다시 오지 않는다. 앱을 다시 켜거나 기기를 바꿔도 같다.
- 넘긴 동물은 최신 넘김 순으로 조회되며 현재 찜 여부를 함께 준다.
- 인증 회원은 찜을 멱등하게 추가·해제하고 최신 찜 순으로 조회할 수 있다.
- 찜을 해제해도 그 동물은 후보 목록으로 돌아오지 않는다.
- 자격을 잃은 찜·넘김은 `UNAVAILABLE`로 남아 목록에서 사라지지 않는다.
- 회원 탈퇴 즉시 찜·넘김 조회가 차단되고 관계형 파기 시 두 행이 함께 제거된다.
- 성격·궁합·안락사 위험처럼 원천으로 검증할 수 없는 주장을 응답과 화면 문구에 포함하지 않는다.
