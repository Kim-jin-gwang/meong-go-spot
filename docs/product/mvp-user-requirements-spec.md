## 1. 문서 목적

본 문서는 멍고반점 MVP가 제공해야 하는 사용자 관점의 기능과 품질 요구사항을 정의한다. 각 요구사항은 구현·테스트·MVP 완료 여부를 판단하는 기준으로 사용한다.

세부 API, 데이터베이스, AI 모델 및 화면 구현 방식은 별도 설계 문서에서 결정한다.

## 2. 서비스 개요

멍고반점은 유실 반려동물 보호자가 사진과 실종 정보를 등록하면, 이미지 유사도를 바탕으로 전국 보호센터 입소 동물과 사용자 `보호하고 있어요` 게시물의 후보를 Top-K로 제시하는 서비스다.

- `잃어버렸어요` 사용자는 사진, 실종 일시·장소 등 정보를 입력해 게시물을 등록한다.
- `보호하고 있어요`에는 사용자 발견·보호 게시물과 보호센터에서 수집한 보호동물 게시물이 함께 표시된다.
- 서비스 시작 시 보호센터의 기존 대상 데이터를 한 번 전체 적재하고, 이후 매일 신규 데이터를 증분 적재한다.
- `잃어버렸어요` 게시물 작성자는 본인의 활성 게시물 상세에서 `유사도 분석하기`를 선택해 사용자·보호센터의 `보호하고 있어요` 후보를 확인한다.
- 게시물 등록, 보호센터 데이터 적재 또는 정기 작업만으로 유사도 분석을 자동 실행하지 않는다. 분석은 사용자가 버튼을 선택한 시점의 DB 내 전체 검색 대상에 대해서만 실행한다.
- 알림은 유사 후보를 자동 안내하지 않는다. 매일 새로 적재된 보호동물 수와 보호소 수는 요약
  푸시와 앱 내 요약으로, 개인 채팅의 새 메시지는 본문 없는 FCM data 알림으로 안내한다.

## 3. MVP 범위

### 3.1 포함 범위

- 개인정보 수집·이용 동의 1개와 휴대전화 번호 수집·인증, 동일 번호 중복 활성 계정 제한을 포함한 회원가입, 로그인, 로그아웃
- 비로그인 상태의 `잃어버렸어요`, `보호하고 있어요` 게시물 목록·상세 열람과 출처 배지 표시, 로그인 상태의 후보 열람과 정확한 위치 확인
- `보호하고 있어요` 최초 진입 시 지역 선택과 선택 지역 게시물 필터링
- 두 공개 게시물 목록의 최신순·오래된순 선택. 기본은 최신순이며 공공 게시물의 등록 기준 시각은 공고 시작일을 우선한다.
- 사진 1장 이상 10장 이하 업로드와 사진 품질 안내
- 본인 활성 `잃어버렸어요` 게시물 상세의 `유사도 분석하기` 버튼과 `보호하고 있어요` 후보 온디맨드 분석
- 분석 요청 후 로딩, 유사 후보 Top-K 또는 후보 없음 결과 표시
- `보호하고 있어요` 게시물 등록 및 선택 지역 목록 반영
- 게시물 수정·종료, 종료 게시물의 공개 목록·후보 비노출과 정확한 위치 정보 공개 동의
- 사용자 게시물 작성자와 닉네임으로 소통하는 1:1 텍스트 채팅, 참여자별 읽음 위치,
  채팅 목록 안 읽음 상태, REST 증분 갱신과 개인 채팅 푸시
- 전국 보호센터 기존 데이터의 최초 전체 적재와 이후 일일 신규 데이터 증분 적재
- 보호센터 공공 데이터를 `보호하고 있어요` 게시물로 표시하고 사용자 게시물과 출처 구분
- 공공 데이터 수집 상태·마지막 갱신 시각 확인과 FCM 푸시·앱 내 일일 신규 보호동물·보호소 수 요약

### 3.2 제외 범위

- 게시물 등록·수정, 보호센터 데이터 적재 또는 스케줄에 의한 백그라운드 유사도 자동 분석
- 새 유사 후보 발생을 감지하는 자동 재분석과 후보 알림
- 유사도 분석 결과의 실시간 푸시 알림
- `보호하고 있어요` 게시물에서 `잃어버렸어요` 후보를 검색하는 역방향 유사도 분석
- 입양 추천·입양 게시판
- 통계·대시보드
- 댓글, 좋아요 등 소셜 커뮤니티 기능
- 채팅 이미지·파일 전송, 그룹 채팅, 메시지 수정·삭제, 차단·신고
- WebSocket·SSE 기반 실시간 채팅
- 유료 결제

`입양 추천·입양 게시판`은 이 핵심 MVP의 인수 범위에 포함하지 않는다. 이후 P1에서 확정한
공공 보호동물 카드 탐색·찜의 최소 범위는 [입양 탐색 P1 MVP 계약](adoption-discovery-mvp.md)을
따르며, 실종 동물 매칭 MVP의 요구사항이나 인수 조건을 변경하지 않는다.

## 5. 용어 정의

| 용어 | 정의 |
| --- | --- |
| `잃어버렸어요` 게시물 | 유실 반려동물 보호자가 자신의 반려동물을 찾기 위해 등록하는 게시물 |
| `보호하고 있어요` 게시물 | 발견자·임시보호자가 등록한 게시물 또는 보호센터 데이터에서 생성한 보호동물 게시물 |
| 보호센터 데이터 | 공공 API 등으로 수집한 보호센터 입소 동물 데이터 |
| 유사 후보 | 업로드한 사진과의 이미지 유사도를 기준으로 제시하는 동물 또는 게시물 |
| Top-K | 유사도 순으로 정렬한 상위 K개의 후보. MVP의 K는 20이다. |
| 후보 없음 | 정상적으로 매칭을 완료했으나 제시 기준을 충족한 후보가 없는 상태 |
| 온디맨드 유사도 분석 | 본인 활성 `잃어버렸어요` 게시물 상세에서 `유사도 분석하기` 버튼을 선택한 경우에만, 요청 시점 DB의 전체 `보호하고 있어요` 검색 대상을 사용해 실행하는 분석 |
| 선택 지역 | `보호하고 있어요` 목록에 표시할 게시물의 5자리 `EVENT.regionCode` 기준 시·군·구 지역 |
| 일일 입소 요약 알림 | 일일 보호센터 증분 적재가 성공한 뒤, 알림을 허용하고 `daily-intake-summary` 토픽을 구독한 기기에 푸시로 전달하고 앱에서는 모든 사용자가 확인할 수 있게 하는 요약. 당일 새로 등록된 보호동물 수와 해당 보호소 수를 안내하며 개별 유사 후보를 안내하지 않는다. |
| 회원 휴대전화 번호 | 회원가입 시 번호 소유 확인, 동일 번호 중복 활성 계정 제한, 계정 관리와 적법한 요청에 따른 안전 대응을 위해 수집·인증하는 개인정보. 다른 회원에게는 공개하지 않는다. |
| 개인정보 수집·이용 동의 | 현재 `privacy-collection-v1`에 대한 회원가입 필수 동의. 가입 정보와 기능 사용 시 처리하는 게시물·사진·위치·선택 좌표·채팅, 처리 목적과 보유 기간을 알리고 회원 행에 버전·시각을 저장한다. 탈퇴 즉시 접근을 차단하고 계정 보호값과 사용자 생성 데이터는 30일 이내 파기·익명화한다. 마케팅·제3자 제공 동의는 MVP에 포함하지 않는다. 실제 고지문은 운영 배포 전에 별도 승인한다. |
| 내부 채팅 | 개인 연락처를 공개하지 않고 사용자 게시물 작성자와 요청자가 닉네임으로 대화하는 1:1 텍스트 채팅 |
| 채팅 읽음 위치 | 참여자마다 해당 대화방에서 화면에 표시한 마지막 메시지 ID. 조회만으로 바꾸지 않고 명시적인 읽음 갱신 요청으로 앞으로만 이동한다. |
| 개인 채팅 알림 | 새 메시지 DB 저장이 완료된 뒤 수신자의 활성 인증 세션에 등록된 기기에 채팅 본문 없이 방·메시지 식별자만 보내는 FCM data 알림. 메시지 전달과 읽음 여부의 최종 기준은 DB다. |

## 6. 요구사항 작성 규칙

### 6.1 식별자

| 접두어 | 구분 |
| --- | --- |
| UR-ACC | 계정 |
| UR-COM | 게시물 열람 |
| UR-IMG | 이미지 입력 |
| UR-OWN | 유실 반려동물 보호자 |
| UR-FND | 발견자·임시보호자 |
| UR-RPT | 게시물 관리·소통 |
| UR-DAT | 데이터 연계 |
| UQR | 품질 |

### 6.2 우선순위

| 우선순위 | 정의 |
| --- | --- |
| Must | 없으면 MVP 출시가 불가능한 요구사항 |
| Should | MVP에 중요하지만 일정상 후속 처리 가능한 요구사항 |
| Could | 여유가 있을 때 포함하는 요구사항 |
| Won't | 이번 MVP에서는 구현하지 않는 요구사항 |

### 8.6 데이터 적재·관리·알림

사용자 게시물과 보호센터 게시물은 동일한 `보호하고 있어요` 목록과 후보군에 표시되지만, 출처에 따라 제공 정보와 가능한 행동이 다르다. 일반 목록은 출처 배지만 표시하고, 상세에서는 사용자 게시물의 작성자 닉네임과 1:1 채팅(로그인 필수), 보호센터 게시물의 보호소 이름·공식 연락처·데이터 갱신 정보를 제공한다. 유사 후보에는 후보 확인에 필요한 출처별 정보를 표시한다. 사용자 게시물은 작성자만 수정·종료할 수 있으며 일반 사용자는 보호센터 게시물을 수정·종료할 수 없다. 사용자가 적절한 연락 방법과 정보의 관리 주체를 판단할 수 있도록 출처를 구분해 표시한다.

## 12. MVP 인수 조건

1. 모든 Must 요구사항이 승인되고 인수 기준을 통과한다.
2. 비로그인 사용자는 두 게시물 유형의 목록·상세와 게시물 출처 배지를 확인할 수 있으며, 후보 조회·등록·수정·종료·채팅과 정확한 위치 확인부터 로그인을 요구한다(v1.23 QA 개정).
3. 선택 지역이 없는 사용자는 `보호하고 있어요` 최초 진입 시 시·군·구 코드를 선택하고, 이후 해당 `EVENT.regionCode`가 같은 활성 게시물을 최신순 또는 오래된순으로 확인할 수 있다.
4. ACT-01은 로그인 후 `잃어버렸어요`를 등록하고, 본인 활성 게시물 상세의 `유사도 분석하기`를 선택해 현재 DB의 전체 `보호하고 있어요` 검색 대상에 대한 후보 있음·후보 없음·실패 결과와 후보 상세를 확인할 수 있다.
5. ACT-02는 로그인 후 `보호하고 있어요` 게시물에 발견 장소 `EVENT`와 현재 보호 장소 `CURRENT`를 모두 입력해 등록하고, 해당 게시물이 이후 `잃어버렸어요` 온디맨드 분석의 후보 데이터로 사용됨을 확인할 수 있다.
6. 게시물 등록·수정, 보호센터 데이터 적재 또는 스케줄만으로 유사도 분석을 실행하지 않고, `잃어버렸어요` 작성자의 `유사도 분석하기` 선택 시에만 분석을 실행한다. `보호하고 있어요` 상세에서는 역방향 분석을 제공하지 않는다.
7. 사용자가 동물을 찾거나 목적을 완료해 게시물을 종료하면 해당 게시물은 공개 목록·검색·신규 후보에서 즉시 제외된다.
8. 최초 운영 데이터 구축 시 보호센터의 기존 대상 동물을 각각 `보호하고 있어요` 게시물로 한 번 전체 적재하고, 이후 일일 신규 데이터를 중복 없이 증분 적재한다.
9. 일일 증분 적재가 성공적으로 완료되면 알림을 허용하고 `daily-intake-summary` 토픽을 구독한 기기에 신규 보호동물 수와 집계 가능한 보호소 수를 푸시로 한 번 제공하고, 모든 사용자는 앱 내에서 동일 요약을 확인할 수 있다. 개별 유사 후보 알림은 제공하지 않는다.
10. 일반 게시물 목록에서는 사용자 게시물과 보호센터 데이터를 출처 배지로 구분한다. 상세에서는 각각 작성자 닉네임 또는 보호소 이름·공식 전화번호를 표시한다.
11. 목록은 모든 게시물에 대해 사건 위치 `EVENT.publicLocation`의 시·군·구 및 읍·면·동 수준 공개 지역만 표시한다. 정확한 위치의 기본값은 역할별 `OFF`이고 `exact-location-v1` 안내 확인 뒤 켤 수 있다. 정확한 주소·건물명·좌표는 비로그인 사용자에게 절대 노출하지 않고, 다른 회원의 활성 사용자 게시물 로그인 상세에서는 `EVENT`와 해당 시 `CURRENT` 각각의 공개 선택과 현재 버전 동의 증빙이 있을 때만 정확한 위치를 표시한다. 목록·검색·후보·종료·삭제·공공 게시물에는 다른 회원용 정확한 위치를 표시하지 않는다. 작성자 관리용 상세는 자신의 저장 위치와 공개 상태를 복원할 수 있지만 좌표는 작성자에게도 숨긴다. 공공 보호동물의 보호소 전체 주소는 로그인 상세에서만 제공한다.
12. 회원가입 시 현재 `privacy-collection-v1` 동의와 인증된 휴대전화 번호가 필수이며 동의 버전·시각을 기록한다. 같은 번호의 활성 계정은 하나만 허용하고 번호를 다른 회원에게 노출하지 않는다. A5 탈퇴는 즉시 세션·공개를 차단하며 30일 개인정보 파기 뒤 같은 번호 재가입을 허용한다.
13. 게시물 등록·채팅 전송·처리 중 매칭 재요청은 클라이언트 또는 실행 식별자로 멱등 처리한다.
14. 성능·Recall@20·데이터 커버리지 목표는 평가 데이터·측정 조건을 확정한 후 검증한다.
15. 새 채팅 메시지는 상대방의 연결 여부나 FCM 수신 성공과 무관하게 DB에 저장되고, 채팅 목록의
    안 읽음 수와 대화 화면의 REST 증분 조회로 확인할 수 있다. 읽음 위치는 화면에 표시한 메시지까지
    명시적으로 갱신하며 이전 위치로 돌아가지 않는다.
16. 개인 채팅 푸시는 등록된 현재 계정의 기기에만 본문 없는 data payload로 발송하고, 수신만으로
    읽음 처리하지 않는다. 계정 전환·로그아웃·탈퇴와 영구 토큰 오류에서는 이전 소유자의 등록을
    해제하거나 정리한다.
