## 화면별 상세

<!-- AI 에이전트는 이미지보다 이 텍스트를 1차로 참조한다. -->

### 01. 홈

- **구성 요소**: 서비스 소개, `잃어버렸어요`·`보호하고 있어요` 진입 버튼, 주요 특징 안내
- **동작**: 비로그인 상태에서도 `잃어버렸어요`는 09, `보호하고 있어요`는 10으로 이동
- **상태/예외**: 정적 랜딩이며 인증을 선행하지 않음

### 02. 로그인

- **구성 요소**: 로그인 ID·비밀번호 입력, 로그인 버튼, 회원가입 링크
- **동작**: 비로그인 상태에서 후보·등록·수정·종료·채팅 기능을 선택하면 로그인 후 원래 목적 화면으로 복귀. 상세 열람은 로그인 없이 가능. 회원가입은 03으로 이동
- **상태/예외**: 아이디 미존재·비밀번호 불일치·비밀번호 형식 불일치는 같은 인증 실패 메시지로 안내. `AUTH-004`이면 `Retry-After`의 남은 제한 시간을 표시하고 로그인 버튼을 그동안 비활성화한다. `AUTH-006`이면 1초 뒤 재시도할 수 있는 일시 과부하로 안내한다. 아이디·비밀번호 찾기와 영구 잠금은 MVP 범위가 아니므로 구현 동선에서 제외

### 03. 회원가입

- **구성 요소**: 로그인 ID, 비밀번호·비밀번호 확인, 닉네임, 휴대전화 번호·인증 코드, 개인정보 수집·이용 동의
- **개인정보 고지**: 휴대전화 인증 전에 수집 항목·목적·보유 기간·동의 거부 시 제한을 화면에 표시하고, 처리방침 전문 링크와 기본 해제된 필수 동의 1개를 제공한다. 동의 전에는 인증 문자를 요청하지 않는다.
- **동작**: Android는 두 비밀번호를 NFC로 정규화해 같은지 검사하고 일치할 때만 `passwordConfirm`을 제외한 A1 요청을 보낸다. 휴대전화 번호 인증과 가입용 증명까지 유효하면 가입하고 02로 이동한다.
- **상태/예외**: 비밀번호는 NFC 기준 8~64자이며 공백·탭·줄바꿈·제어·형식 문자를 허용하지 않고 자동으로 제거하지 않는다. 두 입력 불일치, 중복 ID, 휴대전화 인증과 서버 입력 형식 오류를 각 필드에 안내한다. 닉네임 중복은 허용한다. `AUTH-006`이면 1초 뒤 재시도할 수 있는 일시 과부하로 안내한다. 붙여넣기·자동 완성·표시 전환을 허용하고 화면 이탈 시 비밀번호 입력 상태를 제거한다. 상세 기준은 [비밀번호 정책](../../password-policy.md)을 따른다.

### 04. 실종동물 등록

- **구성 요소**: 사진 1~10장, 이름(선택), 동물 종류, 품종(선택), 성별, 색상(선택), 실종 날짜·시간·사건 위치(`EVENT`), 특징(선택), `EVENT` 정확한 위치 공개 동의, 등록 버튼
- **동작**: 로그인한 사용자가 등록하면 게시물 상세로 이동해 `NOT_REQUESTED`와 `유사도 분석하기`를 표시한다. 사용자가 버튼을 선택한 뒤에만 M2를 접수하고 05로 이동
- **상태/예외**: 실종 날짜 선택기는 한국 시간 기준 오늘까지만 허용한다. 정확한 위치 공개는 기본 `OFF`이고, `ON` 전환 시 로그인한 사용자의 활성 게시물 상세에만 표시된다는 `exact-location-v1` 안내를 확인한다. 사진 수·필수값 검증 오류는 해당 입력을 안내하고 화면에 유지하며 요청 실패 시 입력값과 재시도 동선을 보존한다.

05~07의 분석 상태·후보 화면은 본인 `ACTIVE USER_POST/LOST` 상세에서만 진입한다.
다른 회원의 게시물 상세 열람은 그 게시물의 후보 조회 권한을 주지 않는다. Android는 M1 호출 전
기준 게시물과 현재 회원을 확인하고, 로그아웃·계정 전환·게시물 종료 또는 서버의 권한·상태 거부 시
폴링을 중단하고 기존 결과 표시를 제거한다.

### 05. 매칭 진행

- **구성 요소**: `PENDING`·`RUNNING` 처리 상태, 로딩 표시, 처리 안내
- **동작**: 서버 권장 간격으로 상태를 조회하고 성공 시 후보 유무에 따라 06 또는 07로 이동. 실패 시 오류 안내·재시도·등록 게시물 수정 동선 제공
- **상태/예외**: 서버가 실제 진행률을 제공하지 않으므로 수치형 진행률을 보장하지 않음. 신규 입소 자동 감시·재비교·푸시 알림 문구는 MVP 화면에 표시하지 않음

### 06. 후보 목록

- **구성 요소**: 내 신고 요약, 후보 사진·날짜·공개 지역·출처·현재 상태, 사용자 작성자 닉네임 또는 보호소 이름·공식 전화번호, 직접 확인 안내
- **동작**: 임계값을 통과한 후보를 유사도 순으로 최대 20건 표시하고 후보 선택 시 08로 이동
- **상태/예외**: 원시 점수·백분율·정확한 거리 값은 표시하지 않음. 종료된 사용자 후보는 제외하고 소급 검색 대상으로 유지된 공공 후보는 현재 상태와 함께 표시

### 07. 후보 없음

- **구성 요소**: 빈 결과 안내, `다시 검색하기`, 등록 게시물 수정, 공개 목록 복귀 동선
- **동작**: 작성자가 다시 검색하면 새 매칭 실행을 접수하고 05로 이동
- **상태/예외**: 신규 입소 자동 재비교와 푸시 알림은 MVP 이후(P1)이므로 제공을 약속하지 않음. 처리 실패는 후보 없음과 구분해 오류 안내를 표시

### 08. 비교 상세

- **구성 요소**: 내 동물과 후보 사진·공개 정보 비교, 출처와 현재 상태, 유사 후보이며 직접 확인이 필요하다는 안내
- **동작**: 사용자 게시물 후보는 작성자 닉네임과 `채팅하기`, 공공 보호동물 후보는 보호소 이름·공식 전화번호·주소 확인 동선 제공
- **상태/예외**: 본인·종료 사용자 게시물과 공공 보호동물에는 채팅 버튼을 표시하지 않음. 원시 점수·백분율·정확한 거리 대신 외형·시간·공개 지역을 정성적으로 확인하도록 안내

### 09. 잃어버렸어요 목록

- **구성 요소**: 검색, 등록 버튼, 최신순·오래된순 드롭다운, 사진·동물 요약·공개 지역·실종 일시·상태·`사용자` 출처 배지를 포함한 실종 신고 카드, 하단 탭
- **동작**: 목록은 비로그인으로 조회. 정렬 변경 시 검색어·지역은 유지하고 목록·커서를 초기화해 첫 페이지부터 다시 조회. 등록 버튼은 로그인 여부를 확인한 뒤 04로, 카드는 로그인 없이 게시물 상세로 이동. 하단 탭은 10으로 이동
- **상태/예외**: 로딩·빈 목록·검색 결과 없음·조회 실패. 검색은 `EVENT.regionCode`, 표시는 `EVENT.publicLocation`을 사용하며 작성자 닉네임·회원 연락처·정확한 위치·좌표는 표시하지 않음

### 10. 보호 중 목록

- **구성 요소**: 검색, 등록 버튼, 최신순·오래된순 드롭다운, 사용자·공공 보호동물 카드, `사용자` 또는 `보호소` 출처 배지, 하단 탭
- **동작**: 목록은 비로그인으로 조회. 정렬 변경 시 검색어·지역은 유지하고 목록·커서를 초기화해 첫 페이지부터 다시 조회. 등록 버튼은 로그인 여부를 확인한 뒤 11로, 카드는 로그인 없이 게시물 상세로 이동. 하단 탭은 09로 이동
- **상태/예외**: 로딩·빈 목록·검색 결과 없음·조회 실패. 검색은 `EVENT.regionCode`, 표시는 `EVENT.publicLocation`을 사용하며 사용자 닉네임·보호소 이름·전화·주소·정확한 위치·좌표는 표시하지 않음. 출처별 상세 정보는 게시물 상세에서 제공

### 11. 보호동물 등록

- **구성 요소**: 사진 1~10장, 동물 기본 정보, 발견 날짜·시간·발견 장소(`EVENT`), 현재 보호 장소(`CURRENT`), 특징(선택), `EVENT`·`CURRENT`별 정확한 위치 공개 동의, 등록 버튼
- **동작**: 로그인한 사용자가 등록하면 10으로 복귀. MVP에서는 역방향 매칭을 실행하지 않고 `잃어버렸어요` 사용자의 후보군에 포함된다는 점만 안내
- **상태/예외**: 발견 날짜 선택기는 한국 시간 기준 오늘까지만 허용한다. `EVENT`·`CURRENT` 공개 스위치는 각각 기본 `OFF`이고 서로 영향을 주지 않으며, `ON` 전환 시 `exact-location-v1` 안내를 확인한다. 자택 상세 주소 대신 주변 랜드마크 입력을 권장한다. 회원 개인 연락처는 입력받지 않으며 보호소 공공 데이터는 사용자가 이 화면에서 등록하지 않고 수집 파이프라인으로 적재한다.

## 검토 메모

### v1 스냅샷과 확정 정책의 차이

아래 항목은 PNG·Figma를 다음에 갱신할 때 제거하거나 문구를 수정한다. 현재 구현 계약에는 포함하지 않는다.

1. 03의 휴대전화 번호 입력: 인증 코드 요청·확인, 재전송 대기와 `pv1` 가입용 증명 흐름을 추가하고 두 체크박스 스냅샷을 현재 `privacy-collection-v1` 필수 동의 1개로 교체한다.
2. 05·07의 자동 재비교·푸시 안내: 신규 입소 감시와 FCM 알림은 MVP 이후(P1)로 이동
3. 06의 유사도 백분율·거리와 08의 정량 추천 근거: 원시 점수·백분율·정확한 거리를 숨기고 정성적 확인 안내로 교체
4. 11의 발견 장소 placeholder와 09·10의 일부 날짜 라벨: 실종/발견 맥락에 맞게 카피 수정
5. 04는 사건 위치(`EVENT`)만, 11은 발견 위치(`EVENT`)와 현재 보호 장소(`CURRENT`)를 모두 입력한다. 목록은 `EVENT.publicLocation`만 표시하고, 정확한 위치는 비로그인 사용자에게 표시하지 않으며 로그인 상세에서도 해당 위치의 공개 동의가 있을 때만 표시한다.
6. 04·11의 사건 날짜는 미래 선택을 막고, 정확한 위치 공개 스위치는 위치별 기본 `OFF`와 `exact-location-v1` 확인 문구를 사용한다. 정확한 위치는 활성 사용자 게시물의 로그인 상세에만 표시하고 좌표는 표시하지 않는다.
7. 화면의 기존 `MeonggoCuisine` 브랜드 문구: 과거 PNG·Figma의 역사적 시각 스냅샷 차이이며 구현 계약이 아니다. 현재 사용자-facing 서비스명은 `멍고반점`이다.
8. 04의 `등록하고 찾아보기`는 게시물 등록 뒤 상세 `NOT_REQUESTED`로 이동하는 문구로 바꾼다. M2는 사용자가 상세의 `유사도 분석하기`를 별도로 선택할 때만 접수한다.
9. 09·10 카드의 닉네임·보호소 상세 정보는 비로그인 목록에서 제거하고 출처 배지만 남긴다. 지역 필터는 문자열이 아닌 5자리 `regionCode`를 사용한다.
10. 09·10의 정렬 화살표는 장식이 아니라 `최신순`·`오래된순` 드롭다운으로 구현한다. 기본값은 최신순이며 선택 변경 시 첫 페이지부터 다시 조회한다.

### 추가 설계가 필요한 화면

- MVP: 일반 게시물 상세, 안 읽음 수가 있는 채팅 목록, 읽음 상태·REST 증분 갱신·개인 알림을
  포함한 1:1 채팅, 게시물 수정·종료, A5 회원 탈퇴와 종료 채팅 읽기 전용 상태
- MVP 이후(P1): 신규 매칭 알림, 역방향 매칭 결과, 입양 추천

채팅은 MVP에 포함한다. 다른 회원의 활성 사용자 게시물에서만 닉네임 기반 1:1 텍스트 채팅을
제공하고, 채팅 목록의 안 읽음 수와 상대방 읽음 표시, `afterMessageId` REST 증분 갱신, 채팅
본문을 포함하지 않는 개인 FCM data 알림을 제공한다. 회원 개인 연락처·첨부파일·그룹 채팅·
메시지 수정·삭제·차단·신고와 WebSocket·SSE는 포함하지 않는다.
